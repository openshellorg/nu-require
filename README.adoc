= nu-require
:toc:

CLI helper library: **require Nushell** as the host shell for tailored tools.

== Idea

Nushell-tailored CLIs call `validate()` near process start:

[source,typescript]
----
import { validate } from "@openshellorg/nu-require";

await validate({ offerInstall: true });
----

Behavior:

. **Already under Nushell** → continue normally.
. **Not under Nushell, but `nu` is on PATH** → print that the tool is relaunching inside Nushell, then re-exec the same binary/argv via `nu -c`. The user can keep invoking `myCLItool` from bash/zsh/pwsh; the process hops into Nushell automatically.
. **`nu` missing** → clear error, link to https://www.nushell.sh/, optionally offer a one-shot install (`winget` / `brew` / docs) when `offerInstall: true`.

PowerShell is **not** treated as an acceptable host for these tailored tools (relaunch-to-Nushell is the bridge, not “support pwsh”).

Pass `relaunch: false` only when you want hard-fail instead of auto-relaunch.

== Status

Early scaffold. Detection and quoting heuristics will harden over time. Loop guard: `NU_REQUIRE_RELAUNCHED` prevents infinite relaunch if host detection still fails after hopping into `nu`.

== API sketch (TypeScript)

[source,typescript]
----
import { validate } from "@openshellorg/nu-require";

// Line 1 of your CLI:
await validate({ offerInstall: true }); // relaunch defaults to true
----

See `packages/nu-require/` for the implementation.
